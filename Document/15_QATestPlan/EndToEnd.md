# e2e QA 상세

## 1. 테스트 범위

e2e 현재 책임 경계와 오류·회귀 경로를 검증한다. 수행 결과를 이 계획 문서에 쓰지 않는다.

## 2. 테스트 환경

상위 QA 환경과 해당 플랫폼을 따른다. 사용자 데이터·실행 중 서비스는 보존하고 격리 프로필·복제 클러스터·별도 포트를 사용한다.

## 3. 테스트 케이스 목록

| TC ID | 대상 ID | 유형 | 목적 | 우선순위 | 상태 |
| --- | --- | --- | --- | --- | --- |
| TC-017 | UF-008, UF-007 | 기능·회귀 | 운영 통합 경로 | Must | Review |

## 4. 테스트 케이스 상세

### TC-017

- 전제 조건: 운영 통합 경로의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 격리 환경에서 시작→등록→새로고침→종료→재시작한다.
- 기대 결과: DB 준비와 브라우저 저장 경계가 분리되고 일정이 같은 프로필에서 복원된다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

## 5. 회귀 테스트 기준

해당 책임의 source 또는 계약 변경 시 위 케이스를 다시 확인한다. 공유 계약 변경은 관련 다른 도메인의 QA와 통합 경로까지 확장한다.

## 6. 확인 필요 사항

권한·동시성·복구·플랫폼·시각 적합성 검증을 자동 통과로 처리하지 않는다.
