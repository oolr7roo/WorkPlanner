# web QA 상세

## 1. 테스트 범위

web 현재 책임 경계와 오류·회귀 경로를 검증한다. 수행 결과를 이 계획 문서에 쓰지 않는다.

## 2. 테스트 환경

상위 QA 환경과 해당 플랫폼을 따른다. 사용자 데이터·실행 중 서비스는 보존하고 격리 프로필·복제 클러스터·별도 포트를 사용한다.

## 4. 테스트 케이스 상세

### TC-001

- 전제 조건: 월·주·일·기간 탐색의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 월·주·일의 선택 버튼·날짜 문구·이전/다음/오늘을 확인한다. 같은 기준 날짜로 전환되는지, 모달 취소 후 보기와 일정 집합을 유지하는지 확인한다. COMMON 결합 입력의 선택 states·배치도 각 보기에서 대조한다.
- 기대 결과: 일정 집합이 동일하고 표시 기간·보기 상태가 달라진다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-002

- 전제 조건: 일정 등록의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 제목·시작·종료·색상을 입력하고 저장한다.
- 기대 결과: UUID가 있는 일정이 추가되고 모달이 닫힌다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-003

- 전제 조건: 일정 수정의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 기존 일정을 열고 제목·시간·색상을 바꿔 저장한다.
- 기대 결과: 같은 ID가 유지되고 내용만 변경된다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-004

- 전제 조건: 일정 삭제의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 기존 일정을 열어 삭제한다.
- 기대 결과: 해당 ID만 없어지고 모달이 닫힌다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-005

- 전제 조건: 이동·리사이즈의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 주·일 보기에서 일정을 이동·늘린다.
- 기대 결과: 같은 ID의 시작·종료가 callback 결과와 일치한다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-006

- 전제 조건: 취소 경계의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 초안을 바꾼 후 취소·닫기·배경 클릭을 각각 수행한다.
- 기대 결과: 기존 일정 집합이 변경되지 않는다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-007

- 전제 조건: 보존·복원의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 격리 프로필에서 저장하고 같은 origin을 새로고침한다.
- 기대 결과: 지원 필드가 같은 내용으로 복원된다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-008

- 전제 조건: 입력·저장 오류의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 빈 제목·종료<=시작·격리 저장 실패를 각각 확인한다.
- 기대 결과: 입력 오류는 상태 유지, 저장 실패는 경고 표시; 서버 저장을 주장하지 않는다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-009

- 전제 조건: 손상 데이터·origin 경계의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 격리 프로필에 손상·비배열·잘못된 항목을 넣고 로드한다.
- 기대 결과: 코드의 빈 배열·필터 동작과 덮어쓰기 위험을 기록한다; 원본 보존 보장 없음.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-016

- 전제 조건: 반응형·접근성의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 각 월·주·일 보기를 1440×1000·390×844에서 대조한다. 모바일 주 보기의 SDK 반응형 열 수, 시간표 스크롤·sticky·겹침을 확인하고 키보드·dialog·alert를 확인한다. 작성용 JSON과 결합 JSON의 검증 범위를 구분한다.
- 기대 결과: 현 상태를 기록하며 잘림·포커스·대비 문제가 있으면 통과로 처리하지 않는다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

## 5. 회귀 테스트 기준

해당 책임의 source 또는 계약 변경 시 위 케이스를 다시 확인한다. 공유 계약 변경은 관련 다른 도메인의 QA와 통합 경로까지 확장한다.

## 6. 확인 필요 사항

권한·동시성·복구·플랫폼·시각 적합성 검증을 자동 통과로 처리하지 않는다.
