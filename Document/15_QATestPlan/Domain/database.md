# database QA 상세

## 1. 테스트 범위

database 현재 책임 경계와 오류·회귀 경로를 검증한다. 수행 결과를 이 계획 문서에 쓰지 않는다.

## 2. 테스트 환경

상위 QA 환경과 해당 플랫폼을 따른다. 사용자 데이터·실행 중 서비스는 보존하고 격리 프로필·복제 클러스터·별도 포트를 사용한다.

## 3. 테스트 케이스 목록

| TC ID | 대상 ID | 유형 | 목적 | 우선순위 | 상태 |
| --- | --- | --- | --- | --- | --- |

## 4. 테스트 케이스 상세

### TC-010

- 전제 조건: DB 준비와 재실행의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 복제 클러스터에서 calendarapp 존재·부재 각각 준비한다.
- 기대 결과: 존재 시 생성 생략, 부재 시 생성; 일정 테이블 생성 없음.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

### TC-011

- 전제 조건: 권한·동시 준비·복구의 원본 구현·계약이 존재하고 격리 환경이 준비됨.
- 절차: 격리 복제본에서 관리자 인증 실패·동시 준비·검증 백업 복원을 확인한다.
- 기대 결과: 실패가 상위로 전달되고 데이터 손실 없음; 복구 목표를 실측해 기록한다.
- 대체 확인 방법: 관련 source·설정·콜백·명령 계약을 정적으로 대조하고 동적 검증 미실행을 명시한다. 대체 확인은 실행 통과와 다르다.

## 5. 회귀 테스트 기준

해당 책임의 source 또는 계약 변경 시 위 케이스를 다시 확인한다. 공유 계약 변경은 관련 다른 도메인의 QA와 통합 경로까지 확장한다.

## 6. 확인 필요 사항

권한·동시성·복구·플랫폼·시각 적합성 검증을 자동 통과로 처리하지 않는다.
