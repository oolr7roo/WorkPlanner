# 기능 요구사항

현재 기능 기준선이다. 2026-10-23 승인된 공통 저장소·MCP 제어·명시적 레거시 이전을 포함한다. 전체 품질 승인 상태는 Review다.

## 기능 목록

### UF-001 달력 탐색

앱을 연다. 동일 일정 집합의 표시 범위를 전환한다.

```text
├─ FR-001 현재 기간 및 월·주·일 보기 탐색
│  └─ NFR-003 참조
```

### UF-002 일정 등록

새 일정을 시작한다. 유효한 입력을 새 일정으로 반영하고 편집 상태를 닫는다.

```text
├─ FR-002 새 일정 입력과 등록
│  └─ NFR-001 참조
├─ FR-008 제목·기간 오류 및 저장 실패 안내
│  └─ NFR-002 참조
```

### UF-003 일정 수정

기존 일정을 선택한다. 같은 일정의 내용을 갱신하고 편집 상태를 닫는다.

```text
├─ FR-003 기존 일정 내용 갱신
│  └─ NFR-001 참조
```

### UF-004 일정 삭제

기존 일정을 선택한다. 선택 일정만 제거하고 편집 상태를 닫는다.

```text
├─ FR-004 선택 일정 삭제
│  └─ NFR-001 참조
```

### UF-005 기간 직접 조정

일정을 다른 시간으로 이동하거나 길이를 바꾼다. 달력이 전달한 시작·종료값으로 해당 일정을 변경한다.

```text
├─ FR-005 일정 이동·길이 조정 결과 반영
│  └─ NFR-001 참조
```

### UF-006 편집 취소

편집 중 취소하거나 닫는다. 초안을 저장하지 않고 달력으로 돌아간다.

```text
├─ FR-006 편집 초안을 반영하지 않고 종료
│  └─ NFR-002 참조
```

### UF-007 기존 일정 다시 사용

같은 공통 저장소에 연결한 앱을 다시 연다. 저장된 기록 중 지원 형식인 일정들을 복원한다.

```text
├─ FR-007 같은 사용 환경의 일정 보존·복원
│  └─ NFR-001 참조
```

### UF-008 로컬 실행 관리

시작 명령을 실행한다. 웹 실행 환경과 관리 중인 저장 기반을 종료한다.

```text
├─ FR-009 설정 검증과 로컬 실행·종료 제어
│  └─ NFR-004 참조
├─ FR-010 로컬 데이터베이스 존재 확인·준비
│  └─ NFR-004 참조
├─ FR-011 데이터베이스 프로세스 시작·정지 관리
│  └─ NFR-004 참조
├─ FR-012 웹 제공과 DB 파일 접근 차단
│  └─ NFR-005 참조
```

### UF-009 단계별 색상 설정

설정을 열어 프리셋을 선택·추가하고 단계 색상을 미리 확인한 뒤 저장하거나 취소한다.

```text
├─ FR-013 단계별 색상 프리셋 편집·선택·보존
│  ├─ NFR-001 참조
│  └─ NFR-002 참조
```

### UF-002·UF-003 색상 선택 확장

새 일정은 단계별 자동 색상을 사용하고 기존 일정은 저장된 색상을 유지한다. 공통 설정에서 자동 색상을 일괄 적용하며 개별 일정은 헤더의 색상 선택·자동 복원으로 전환한다. 개별 지정 색상은 공통 설정 변경 시 유지한다.

```text
├─ FR-014 일정 단계별 자동 색상 및 직접 지정 우선 적용
│  └─ NFR-001 참조
```

## UF-002 / UF-003 일정 체크리스트

일정별 항목을 추가·수정·완료 체크·삭제하고 완료 개수를 표시한다. 저장하면 반영하고 취소하면 원본을 유지한다. 체크리스트가 없는 기존 일정도 편집할 수 있으며 기간·계층·우선순위에 영향을 주지 않는다.

```text
├─ FR-015 일정별 체크리스트 편집과 보존
│  ├─ NFR-001 참조
│  └─ NFR-002 참조
```

### UF-001·UF-002·UF-003 계획과 작업 구분

일정 구분을 계획 또는 작업으로 선택·보존한다. 우선순위는 전체를, 간트·월·주·일은 작업만 표시한다. 기존 구분 없는 일정은 작업으로 유지하며 표시 필터는 계층·기간·색상을 변경하지 않는다.

```text
├─ FR-016 계획·작업 구분과 작업 중심 표시
│  ├─ NFR-001 참조
│  └─ NFR-002 참조
```

### UF-010·UF-011 공통 일정과 AI 연결

```text
├─ FR-017 웹·AI가 동일한 일정과 색상 설정을 보존·조회·변경
│  ├─ NFR-001 참조
│  └─ NFR-002 참조
├─ FR-018 로컬 MCP로 일정 검색·생성·수정·계층·순서·삭제 제어
│  ├─ NFR-001 참조
│  └─ NFR-005 참조
├─ FR-019 기존 브라우저 일정의 미리보기·원본 보존·원자적 가져오기
│  ├─ NFR-001 참조
│  └─ NFR-002 참조
```

같은 수정 버전으로 동시에 변경하면 하나만 반영하고 나머지는 충돌을 알린다. 동일 요청 재시도는 중복 생성하지 않는다. 계획과 하위 작업 일괄 생성은 모두 성공하거나 모두 취소한다. 신규 기본 구분 계획·기존 누락 구분 작업·삭제 시 자식 보존을 유지한다.

## 공통 비기능 요구사항

### NFR-001

- 적용 기능: FR-002, FR-003, FR-004, FR-005, FR-007, FR-013, FR-014, FR-015, FR-016, FR-017, FR-018, FR-019
- 요구사항: 공통 서버 저장이 성공한 경우 웹과 AI에서 변경한 제목·시간·색상·체크리스트·구분와 일정 식별자는 새로고침 뒤 동일해야 한다.
- 검증 기준: 정상 보존 사례의 변경 전후 기록 비교; 저장 실패는 보존 보장 제외

### NFR-002

- 적용 기능: FR-006, FR-008, FR-013, FR-015, FR-016, FR-017, FR-019
- 요구사항: 유효하지 않은 기간 저장과 편집 취소는 기존 일정 집합을 변경하지 않아야 하며, 저장 실패 시 오류 안내가 표시되어야 한다.
- 검증 기준: 입력 실패·취소 전후 일정 집합이 동일하고 저장 실패 안내가 관찰됨

### NFR-003

- 적용 기능: FR-001
- 요구사항: 한국어 월·주·일 선택과 기간 탐색 후 일정 데이터가 변하지 않아야 한다.
- 검증 기준: 보기 변경 전후 동일 일정 집합; 선택 보기 버튼의 눌림 상태 확인

### NFR-004

- 적용 기능: FR-009, FR-010, FR-011
- 요구사항: 준비 실패 시 웹 준비 완료로 표시하지 않아야 하며 정상 종료 후 감독 프로세스 상태가 stopped여야 한다.
- 검증 기준: 시작 오류 종료 코드와 상태 확인; 실제 DB 종료는 별도 프로세스 상태 검증

### NFR-005

- 적용 기능: FR-012, FR-017, FR-018, FR-019
- 요구사항: 웹과 DB 리스너는 loopback에서 제공되고 웹 경로를 통한 PostgreSQL 디렉터리 요청은 404로 거부되어야 한다.
- 검증 기준: 리스너 설정 및 DB 경로 응답 확인

## 확인 필요 사항

성능 상한·지원 브라우저 공식 범위·키보드 접근성 적합성·가용성 SLA는 측정 또는 승인 근거가 없다. 현재 기준선에 수치를 만들어 넣지 않는다.

## FR-018 AI 신규 일정 등록 전 확인

신규 AI 일정 제어는 초안 제출·상태 조회와 웹에서의 명시적 확정으로 분리한다. 초안은 실제 일정과 별도 보관하며 제목·계획/작업·기간·색상·체크리스트·등록 대상을 편집할 수 있다. 확인한 미리보기와 저장 내용이 일치해야 한다. 일정·초안 버전 충돌은 입력을 보존하고 재확인하며, 같은 등록 요청 재시도는 중복 생성하지 않는다. MCP 즉시 생성 도구는 제거하고 웹 확정 API는 bearer로 호출할 수 없다.
