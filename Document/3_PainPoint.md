# CalendarApp 문제 상태

## 1. 문서 목적

관찰된 구현 한계와 사용자 문제 가설을 구분한다. 고객 목표는 4번 문서에서 정의한다.

## 2. 문제 범위

| 포함 / 제외 | 내용 | 이유 |
| --- | --- | --- |
| 포함 | 현재 손실 가능성·환경 의존·개인 일정 관리 불편 가설 | 문제 근거 |
| 제외 | 해결 기능, 우선순위, 품질 목표 | 후속 요구사항 책임 |

## 3. 문제 목록

| ID | 현재 문제 상태 | 분류 | 확인 상태 |
| --- | --- | --- | --- |
| PP-001 | 개인 일정이 분산되어 기간별 상황을 한눈에 파악하기 어렵다는 사용자 문제 가설 | 사용자 불편 | 확인 필요 |
| PP-002 | 브라우저 데이터 삭제·프로필 변경·origin 변경 후 기존 일정에 접근할 수 없다 | 리스크 | 확인 |
| PP-003 | 일정이 여러 기기나 사용자 사이에 공유되지 않는다 | 리스크 | 확인 |
| PP-004 | 일정 저장에 사용되지 않는 DB 실행 실패도 앱 시작을 막는다 | 리스크 | 확인 |
| PP-005 | 저장된 일정의 날짜 유효성·ID 중복·색상 형식까지 검사하지 않는다 | 리스크 | 확인 |

PP-002·003·005의 근거는 [일정 구현](../src/App.tsx), PP-004의 근거는 [실행 관리자](../server.mjs)다. 확인은 코드 관찰을 뜻하며 사용자 발생 빈도나 피해 규모까지 확인했다는 뜻은 아니다.
