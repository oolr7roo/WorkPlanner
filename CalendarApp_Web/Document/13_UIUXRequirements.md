# CalendarApp 공통 UI UX 기준

## 1. 문서 목적

현 화면과 모달에서 확인되는 표시·입력·피드백 기준을 정리한다. 월·주·일과 트리 우선순위·간트 보기는 같은 일정 집합과 기준 날짜를 사용한다.

## 3. 제품 UX 원칙

같은 일정 집합을 기간별로 살펴보고 편집한다. 저장 범위는 브라우저로 안내하며 서버 동기화 성공으로 오인할 표현을 사용하지 않는다. 입력 실패 시 초안을 유지하고 수정 기회를 제공한다.

## 4. 공통 인터랙션 기준

| 인터랙션 | 기준 | 적용 범위 | 예외 |
| --- | --- | --- | --- |
| 선택 | 현재 선택한 보기 상태를 구분 | 달력 탐색 | 선택 상태는 저장되지 않음 |
| 입력 | 제목·현지 날짜시간·색상 입력 | 편집 모달 | 날짜 형식은 브라우저 제공 UI |
| 시작 변경 보정 | 기존 일정 수정 중 새 시작 ≥ 종료이면 변경 직전 유효 초안의 기간만큼 종료도 이동 | MOD-001의 수정 가능한 리프 일정 | 빈 입력·잘못된 기간·신규 생성은 보정하지 않음; 종료 직접 변경 시 시작 유지 |
| 취소 | 초안을 일정에 반영하지 않고 종료 | 생성·수정 상태 | 삭제 실행에는 되돌리기 없음 |
| 좁은 화면 | 시간 입력을 한 열로 표시 | 700px 이하 | 달력의 최소 높이로 세로 overflow 가능 |

## 5. 피드백 / 상태 기준

| 상태 | 기준 | 표시 방식 | 적용 범위 |
| --- | --- | --- | --- |
| 입력 오류 | 편집 유지 | 텍스트 alert | 모달 |
| 저장 오류 | 메모리 변경은 유지 | 텍스트 alert | 달력 하단 |
| 저장 성공 | 별도 토스트 없음 | 일정 표시 갱신·모달 종료 | 일정 관리 |
| 읽기 오류 | 빈 목록과 변경 차단 | 원본 보존 경고 | 초기 로드 |

## 6. 접근성 기준

제목 입력 autofocus, 모달 dialog·aria-modal·aria-labelledby, 닫기·기간 이동 aria-label, 보기 aria-pressed, 오류 role=alert가 확인된다. 키보드 Tab·Enter 기본 조작은 브라우저를 따른다. 편집창은 native dialog의 모달 포커스·Escape·복귀 동작을 사용한다. WCAG 준수나 대비율 충족은 미검증이다.

## 7. 디자인 시스템 기준

주 행동은 파랑, 삭제·오류는 붉은 계열, 일반 배경은 밝은 회색·흰색이다. 한국어 시스템 글꼴을 사용하고 입력과 버튼에 둥근 테두리와 포커스 표시를 제공한다. 상세 크기·배치는 source와 화면 JSON에서 관리한다.

## 8. 공통 컴포넌트 / 패턴 기준

COMMON은 반복 구조를 정의하고 각 SCR은 선택 상태·날짜 문구·배치를 공급한다. 날짜 예시는 캡처값이며 현재 날짜를 고정하는 규칙이 아니다. 생성·수정은 같은 모달 패턴을 사용하며 수정 상태에서만 삭제를 제공한다. 월·주·일은 SDK가 렌더링하며 트리 목록·간트·빈 상태는 앱이 렌더링한다. 검색·필터·로딩·저장 중 화면은 새 패턴으로 정의하지 않는다.

## 9. 확인 필요 사항

모바일 달력 잘림·시간 표기 줄바꿈·스크린 리더·포커스 이동·대비율은 관찰된 한계를 포함해 검증 보고서에서 추적한다.

## 트리·간트 기준

숫자 우선순위 대신 parentId/order로 형제 간 배치 순서를 사용한다. SCR-005는 접고 펴는 트리 목록이며 SCR-004도 같은 트리 순서와 접힘 상태를 공유한다. 들여쓰기는 단계당 8px, 최대 24px이다. 제목 클릭은 펼침·접힘, 별도 편집 버튼은 MOD-001을 연다. 부모 대표 기간은 하위 일정 범위이며 삭제 시 자식은 한 단계 위로 보존한다. 기존 v1 데이터는 변경하지 않고 v2로 변환한다.

Space로 순서 이동을 시작하고 방향키로 위치 선택, Enter 확정, Escape 취소한다. 드래그는 같은 부모 안에서만 허용한다. 간트는 2주 기간·고정 일정명 열·고정 날짜 헤더·가로/세로 스크롤을 제공한다.
