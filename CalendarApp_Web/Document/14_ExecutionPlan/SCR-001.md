## 5. 리스크 / 차단 사항

현재 구현은 존재하나 전체 인수 검증 전이므로 Task 상태는 Review다. UI·업무·저장은 features/schedules와 공통 툴바로 분리한다. 별도 MVVM·Service Interface가 이미 구현된 것으로 서술하지 않는다. DB 운영·Windows 전체 프로세스 검증은 미실행이며 미실행을 구현 부재와 혼동하지 않는다.

JSON 연결 정본: [SCR-001](../09_WireframeMockup/SCR-001.json), [MOD-001](../09_WireframeMockup/MOD-001.json). Source: [App](../../../src/App.tsx).

주·일 본문은 [SCR-002](SCR-002.md), [SCR-003](SCR-003.md)가 소유한다. 공유 정의와 문서 결합은 TASK-001 한 곳에서 관리한다. TASK-002는 월 보기 calendar 콜백을 검증하며 타 보기의 상세 구조를 변경하지 않는다.


## 2026-10-21 트리 일정 구현 기준선

숫자 우선순위 대신 parentId/order로 형제 간 배치 순서를 사용한다. SCR-005는 접고 펴는 트리 목록이며 SCR-004도 같은 트리 순서와 접힘 상태를 공유한다. 들여쓰기는 단계당 8px, 최대 24px이다. 제목 클릭은 펼침·접힘, 별도 편집 버튼은 MOD-001을 연다. 부모 대표 기간은 하위 일정 범위이며 삭제 시 자식은 한 단계 위로 보존한다. 기존 v1 데이터는 변경하지 않고 v2로 변환한다.


단계별 색상 확장: FR-013·014 → COMMON-001/MOD-001/MOD-002 → MOD-EventManagement → DATA-002·004/API-001. 순수 정책·설정 상태와 팝업의 상세 소유는 TASK-003이며 저장 어댑터·App 조립은 기존 TASK-001이 담당한다. [범위 검증](../Evidence/ColorPresets/README.md)을 확인했다. 전체 문서·인수 상태는 Review를 유지한다.
