# TASK-002 삭제·취소의 반영 경계 확인

## 1. 작업 목적과 전체 처리 흐름

소유 작업 흐름: [MOD-EventManagement](../MOD-EventManagement.md). 현재 구현 기준선 검증 Task이며 새 기능 구현 완료 기록이 아니다. FR 범위: FR-002, FR-003, FR-004, FR-006, FR-008.

```text
소유 흐름·SRS 확인 → 현재 source·계약 대조 → 비파괴 검증 → 증거 기록 → Review 유지 또는 검증 완료 판정
```

- 실행 모드: SEQUENTIAL
- 병렬 그룹: NONE
- Write Set: 없음. 재실행 검증에서 구현 source를 수정하지 않는다.
- Read-only Shared Set: src/App.tsx, 관련 SRS·9~13번 원문

## 2. 단계별 실제 작업

### 단계 1 — 입력 기준선 확인

- 목적: 삭제·취소의 반영 경계 확인의 현재 범위를 확정한다.
- 입력 기준: 소유 2단계 문서, SRS의 FR-002, FR-003, FR-004, FR-006, FR-008.
- 처리 과정: deleteEvent의 ID 필터와 편집 종료 경계를 확인한다. 삭제는 즉시 반영하며 취소·닫기·배경 클릭은 초안을 반영하지 않음을 확인한다.
- 출력: source·계약·JSON 대조 결과와 미검증 목록.
- 완료 조건: 구현에 없는 동작을 완료로 쓰지 않고 현재 책임이 설명됨.

### 단계 2 — 검증과 판정

- 목적: 정적 확인과 실제 동작 검증을 분리한다.
- 입력 기준: 앞 단계 대조 결과, 현재 실행 환경.
- 처리 과정: 컴파일·빌드·기존 브라우저 검증 또는 승인된 운영 환경에서 검증한다. 운영 데이터 변경이 필요한 사례는 격리 복제본에서만 수행한다.
- 출력: 실행 증거 또는 미실행 사유.
- 완료 조건: 실패·미실행을 통과로 기록하지 않음.

## 5. 리스크·차단 대응과 작업 범위

- 확인 대상 파일: src/App.tsx.
- 생성·수정 대상: 없음. source 변경이 필요하면 현재 Task와 상위 책임표를 다시 판정한다.
- 제외 대상: 클러스터 파일·비밀 파일 내용·사용자 브라우저 데이터·범위 밖 구현.
- 중단 기준: 문서와 source 불일치, 실운영 데이터 쓰기 필요, 기준선 밖 파일 변경 필요.
- 재개 조건: 영향 범위와 검증 환경을 확정하고 해당 owner Task 기준선을 갱신함.
- 현재 결합 위험: Web의 App 내부 UI·업무·저장이 한 파일에 결합됨. 분리된 Interface·Service가 존재한다고 기록하지 않는다.

## 7. 완료 기준과 검증 방법

- 완료 기준: 현재 동작·오류·대상 파일·책임이 source와 계약 문서에 일치함. 동작 검증 증거가 없으면 Review 유지.
- 검증 방법: 빌드·정적 계약 대조·격리 브라우저 확인·별도 운영 검증 중 해당 수단을 사용한다. 신규 테스트 코드 작성은 이 Task 범위에 없다.
- 현재 구현 관찰은 존재 확인이며 QA 전체 통과와 다르다. 실행 증거는 [검증 보고서](../../../../Document/17_ValidationReport.md)에서 관리한다.

## 9. 보기 분리 이후 모달 기준선

MOD-001은 SCR-001~003에서 호출하는 공통 편집 모달이다. entry·exit 문서 관계만 갱신하고 기존 form component·업무 검증·저장 정책은 유지한다. 취소 후 호출한 보기 유지가 격리 실행으로 확인되었다. save·delete 후 각 보기 복귀의 전체 조합은 이번 범위에서 실행하지 않아 Review다. 현재 Write Set은 MOD-001의 문서상 entry·exit·검증 메타데이터와 연결 Task이며 앱 source는 참조 전용이다. 공통 정의·보기 본문은 화면 owner Task 책임이다.
